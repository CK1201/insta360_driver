# Changelog

## [0.4.1] - 2026-11-17

### Features
- 合并重复的超时条件判断，启动时换算一次图像补偿量，清理重复头文件和 Android 未使用导入。

### Design Rationale
- 复用已验证的采集路径，减少重复计算与判断；保留错误优先顺序、手机相机常驻连接及原始数据排空。

### Notes & Caveats
- CLI、YAML、Python 接口和时间戳语义沿用原版本；本次仅做离线验证，无需重装桥接 App。

## [0.4.0] - 2026-11-17

### Features
- 新增 YAML `timing.sensor_delay_s`，默认 0 秒；Python 帧和帧时间 CSV 输出补偿后的 `timestamp_ns`。
- 校验非负有限秒数、纳秒转换与错误参数位置；示例打印补偿时间和原始主机时间。

### Design Rationale
- 参考 specialist-ai 驱动的 arrival − sensor_delay，在图像产出时只补偿一次；采用独立字段以保留原始数据和处理耗时语义。

### Notes & Caveats
- 补偿是主机单调时钟下的图像时间估计，不改变传输延迟，也不代表已测量曝光时间。缺失收包时间时保持 0；手机、相机、IMU 与曝光时间戳均不改。
- 原 YAML 可省略该字段；帧时间 CSV 在末尾新增列。Android 桥接和协议不变。
- 新补偿逻辑通过真实 H.264/H.265 合成流与配置离线回归；本轮未新开相机会话。

## [0.3.0] - 2026-11-17

### Features
- 新增可选 pybind11 原生包 `insta360_go3s`：Reader 后台采集、latest/read、上下文管理、错误状态、停止与重启，以及带主机时间和会话序号的可写 BGR NumPy 帧。
- 新增 scikit-build-core wheel、取帧示例，以及真实 H.264/H.265 桥接数据的 Python 离线回归。

### Design Rationale
- 复用既有 C++ 传输、解码和原始保存路径；每流单槽限制内存，复制交付图像避免后续帧和用户修改相互影响。
- Python 不读 stdin、不打开窗口、不安装信号处理器；等待和停止释放 GIL，后台线程不回调 Python。默认 CLI 构建不依赖绑定工具。

### Notes & Caveats
- 慢消费者可跳过预览序号；原始保存继续排空全部已接受数据。时间是主机单调时钟，不能作为设备曝光时刻。
- 停止电脑 Reader 保留手机前台服务和 GO3S 相机控制连接。wheel 依赖本机 C++/FFmpeg/OpenCV/yaml-cpp 动态库。
- 2026-11-17，五组 CTest（含 15 项 Python 回归）与安装后 wheel 测试通过；实机连续两次取流复用连接，15 秒会话保存 388 帧、6400 条六轴样本、391 条曝光数据，视频全解码、索引与计数核对通过。具体范围见 README。

## [0.2.0] - 2026-11-16

### Features
- 参考已验证的X5路径，为GO3S完整I/P H.264回调增加直接送包及仅解码副本的SPS重排修正，减少解析和重排缓冲。
- 新增像素/接收时间戳一致、零压帧、B帧拒绝、启动旧P帧及完整保存回归，摘要记录实际模式与SPS副本修改次数。

### Design Rationale
- 先确认GO3S回调边界与完整AU相同、实采无B帧及SPS声明4帧重排；只修改预览解码分支，保留通用H264分片/H265 parser和全部原始记录。
- 不增加配置开关或修改Android端，手机保持相机控制连接，电脑启动命令不变。

### Notes & Caveats
- 513帧真实录像回放从5帧等待降为0，像素和时间戳一致；同参数实机电脑收包到解码完成均值166.92→1.03ms，P95 195.60→1.59ms。该测量不是光学端到端或手机到电脑单向时延。
- 保存的码流仍保留相机原始SPS（reorder=4），当前用户ISO/快门/白平衡及其他YAML值不变；未修改X5或CoMM，未发布GitHub。

## [0.1.0] - 2026-11-16

### Features
- GO 3S 通过 Android 9/ARM64 手机桥接，经 Wi-Fi 取流并通过 USB/ADB 交付 Ubuntu 客户端。
- YAML 启动参数、曝光和白平衡读回、实时画面与相机六轴、原始视频/GYRO/时间戳和状态保存。
- 单连接有序协议、两端有界队列、完整性错误及正常排空；提供本地 APK 工具链和离线测试。
- 电脑结束采集或 USB 断开只停止预览，手机保持 GO 3S SDK 控制连接和心跳，后续电脑采集复用该连接；手机“断开相机”才明确释放。

### Design Rationale
- 使用 Camera SDK 2.2.6，手机只控制和转发，视频在电脑解码，不引入 Media SDK 或手机传感器。
- 分开记录相机、手机和电脑时间域，使用 SDK 实际预览尺寸，不移植 X5 分辨率或采样率假设。

### Notes & Caveats
- APK（API28/ARM64）、11项Android单元测试、3组电脑端离线测试及小米6/GO3S自动/手动实机采集分别验证通过；实际解码640×384，视频约30fps、相机IMU约500Hz，六轴单位及轴方向仍未标定。
- SDK 内部分发丢包不可完整观测，应用传输序号连续不等于传感器绝对无丢失或硬同步。
- 本项目独立于现有 X5 驱动，不提供自动重连、FPS 扫描、机内录像、对外网络服务或 GitHub 发布。
